# 生字跟讀小幫手

學生輸入生字 → 取得符合年級的詞語 → 聽讀音、跟讀 → 聽解釋、跟讀 → 下一個詞，一次三輪。教師後臺可設定年級、管理詞語、查看練習紀錄。

```
frontend/          放到 GitHub Pages（學生端與教師後臺）
  index.html       學生端
  admin.html       教師後臺
  tests.html       前端驗證測試（日期三種形態、跟讀比對）
  assets/config.js 只需要改這個檔的 API_URL
backend/           貼到 Google 試算表的 Apps Script
  Code.gs
  appsscript.json
tools/
  prepare_dict.py  整理《國語辭典簡編本》授權資料
```

## 一、建立後端（約 10 分鐘）

1. 新增一份 Google 試算表，命名為「生字跟讀資料庫」。
2. 選單「擴充功能 → Apps Script」。
3. 左側「專案設定（齒輪）」→ 勾選「在編輯器中顯示 appsscript.json 資訊清單檔案」。
4. 回到編輯器，把 `Code.gs`、`appsscript.json` 的內容分別貼上覆蓋，儲存。
5. 上方函式選單選 `setup` → 執行 → 依指示授權。
   完成後「執行紀錄」會顯示**教師密碼**。之後想改密碼：專案設定 → 指令碼屬性 → 修改 `TEACHER_PIN`。
6. 函式選單選 `test_dates` → 執行，確認日期三種形態全部 ✅（含實際寫入試算表再讀回）。
7. 右上「部署 → 新增部署作業」→ 類型選「網頁應用程式」：
   - 執行身分：**我**
   - 誰可以存取：**任何人**
   複製產生的網址（結尾是 `/exec`）。

> 之後修改 `Code.gs`，要用「部署 → 管理部署作業 → 編輯（鉛筆）→ 版本選『新版本』」，網址才會維持不變。

## 二、建立前端（約 10 分鐘）

1. 在 GitHub 新增一個 repository（可設為 Public，GitHub Pages 免費方案需要公開）。
2. 把 `frontend` 資料夾裡的**所有內容**上傳到 repository 根目錄。
3. 編輯 `assets/config.js`，把 `API_URL` 換成上一步的 `/exec` 網址。
4. repository 的 Settings → Pages → Source 選 `Deploy from a branch`，分支選 `main`、資料夾 `/ (root)`，儲存。
5. 約一分鐘後網址會是 `https://你的帳號.github.io/repository名稱/`。
6. 開啟 `…/tests.html`，確認前端測試全部 ✅。

> 程式碼公開不會洩漏資料：學生需要專屬金鑰、後臺需要教師密碼，試算表本身不公開。

## 三、開始使用

1. 開 `…/admin.html`，用教師密碼登入。
2. 「學生」分頁：填暱稱、年級，按「儲存學生」，再複製每位學生的**專屬連結**傳給家長。
3. 系統內建「學」字的範例詞語，可以先輸入「學」試用。

給家長的提醒建議包含：用手機的 Chrome 或 Safari 開啟（從 LINE 點開時，程式會自動跳轉到瀏覽器）、第一次使用請允許麥克風、語音辨識由瀏覽器服務商（Google／Apple）處理，本工具不保存錄音。

## 四、匯入正式詞庫

1. 從教育部「辭典公眾授權網」下載《國語辭典簡編本》資料檔，先確認授權條款。
2. 執行整理腳本（或把下載的檔案上傳給 Claude 代為整理）：
   ```
   pip install pandas openpyxl
   python tools/prepare_dict.py 下載的檔案.xlsx --out output
   ```
3. 在試算表點選「詞庫」工作表 → 檔案 → 匯入 → 上傳 `output/words.csv`：
   - 匯入位置選「**取代目前的工作表**」
   - **取消勾選**「將文字轉換為數字、日期和公式」
4. 同樣方式把 `output/chars.csv` 匯入「字音」工作表。
5. Apps Script 執行 `refreshCache`，學生端立即讀到新資料。

「難度」是腳本依詞長、解釋長短、用字罕見程度估算的起點，請在後臺「詞語」分頁看到不適合的詞就調整或封鎖，用幾週後會越來越貼近班級程度。

## 設計重點

**三段式降級**：瀏覽器支援語音辨識就自動判斷；不支援但有麥克風就改成「錄音回放、自己判斷」；連麥克風都沒有就「念完自己按」。紀錄表「驗證方式」欄會標示是哪一種，後臺的平均正確率只計算自動辨識。

**跟讀比對用注音**：辨識結果轉成注音再比，同音字（公式／公事）不會被誤判；有對齊注音時，破音字的其他讀音不會被算對（銀行念成「銀形」不通過）。解釋跟讀用最長共同子序列計分，預設 80 分通過，念到門檻會自動結束收音。

**語音只用台灣國語**：找不到 `zh-TW` 語音就不播放，改為提示看注音，避免念成其他地區讀音。若日後取得真人錄音，把網址填入「詞庫」的「音檔網址」欄就會優先播放。

**日期防禦性設計**：日期 `yyyy-MM-dd`、時間 `HH:mm:ss` 分欄存純文字；寫入前在伺服器以 `Asia/Taipei` 產生；讀取以 `normalizeDate_()` 寬容解析乾淨字串、Date 物件、Date 長字串；前後端各有測試。離線未送出的紀錄會暫存在手機，恢復連線後補送，並以場次編號避免重複寫入。

**手機輸入**：注音輸入法選字期間不改動輸入框、不使用 `maxlength`（會截斷組字）；以 `visualViewport` 與 `interactive-widget=resizes-content` 處理鍵盤遮擋。

## 已知限制

- 語音辨識看的是「辨識出的字」，辨識引擎可能依上下文猜對詞語，無法百分之百確認破音字的實際發音；建議搭配課堂抽測。
- 裝置語音合成遇到破音字可能念錯；真人錄音是最根本的解法。
- Firefox 與部分 App 內建瀏覽器不支援語音辨識，會自動改用降級模式。
